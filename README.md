## How the photo was made

`promo.png` is a 1024 × 1024 RGB PNG generated by the repository-root
`render-promo.py`, using Pillow 10.2.0 and locally installed DejaVu fonts.
It uses the official **make.fun magenta `#c41c83`**, read from the `brand`
section of `/tmp/press-manifest.json`, with white typography and the official
ghost mark clearly visible in the centre.

The mark came from the official press-pack asset:
<https://make.fun/press/mark-1024.png>. Its 67,068-byte source is stored locally
at `out/mark-1024.png`, with SHA-256:

```text
78fc23c446a592dbc9fb7aa65a770bfc2fff7e108e7b4453326c55f2d923b339
```

The renderer verifies that source against the press manifest before use. The
complete mark is proportionally scaled to 300 × 300 pixels with LANCZOS;
it is not redrawn, recoloured, stretched, rotated, cropped or given effects.
Every text line is measured before positioning, with ample canvas margins
and clear space around the mark.

The image copy is “MAKE YOUR OWN BOUNTY”, “Describe a task. Set the reward.
Keep a share of every fee.” and “make.fun/sponsor/new”. The render uses fixed
positions, no random values, no timestamps and no network requests. With the
official source and press manifest already available locally, regenerate it
from the repository root:

```sh
python3 render-promo.py
```

The finished photo was opened and visually inspected: the central ghost is
clear, the headline and footer are readable, and no text is clipped or
overlapping. Moving the renderer to the repository root and running it again
produced a byte-identical PNG. The older `out/layout-preview.png` is only a
typography proof; attach the finished root-level `promo.png` to the quote.

## Run the program locally

Use Node.js 22.18 or newer; no npm packages or installation step are needed.

```sh
mkdir -p out && MAKEFUN_BOT_DIR=. MAKEFUN_OUTPUT_DIR=out node main.ts
cmp POST.json out/POST.json
```

`main.ts` creates the destination directory and copies `POST.json` byte for
byte. The source directory is `MAKEFUN_BOT_DIR` (default `/bot`); the output
directory is `MAKEFUN_OUTPUT_DIR` (default `/output`). Success is silent.
Directory or copy failures print an error and exit with status 1. The program
does not call X, fetch counts, publish a post or contact make.fun.

## Check before any later submission

From the supplied kit directory, read `node cli/makefun.mjs check --help`,
then run its `check` command against this repository and the real recorded
transcripts. Transcripts are not bundled during this build; a later agent
handles them. No transcripts may be invented, and nothing is submitted here.

On this sandbox, the unmodified checker stops with `spawnSync git EPERM`
when Git has an unused piped stdin. The local helper
`out/check-stdin-compat.cjs` replaces only that unused Git stdin pipe with
`ignore`; the kit's files, validation logic and command results are unchanged.
With that compatibility helper, the kit reaches its checks and fails only
`transcripts_present`, since no transcripts were supplied. Complete raw output
is preserved in `out/kit-check-compat.txt` (worktree) and
`out/kit-check-final.txt` (committed snapshot). All local `out/` helpers and logs are
ignored by Git and are not part of the submitted runtime.

`prompt.txt` preserves the supplied record of the account holder's own words.
`AGENT.md` records the posting handoff and the remaining blockers. The source
and prepared promotional materials are licensed under MIT; the official
make.fun mark remains subject to its press-pack usage requirements.
